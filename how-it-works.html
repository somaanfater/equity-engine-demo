Architecture

How it works

One rule shapes everything else: the language model never does arithmetic. Every number comes from Python or from a cited source. The phases reason over computed figures and request new calculations through tool calls — they are never asked to produce a figure, because a model that can produce one can invent one.

Deterministic — Python, no model AI — a model reasoning over computed numbers Check — can only remove or flag, never add
01

Snapshot

Every source is fetched once and frozen into a hashed directory: SEC filings and XBRL facts, prices, FRED macro series, Form 4 insider transactions, 13F holdings, FINRA short interest, Fama–French factors, the implied equity risk premium, peer financials. Each loader takes an as-of date and must not return anything published after it. Every run and every council seat reads the same frozen snapshot — nothing fetches live data once it is sealed.

point-in-time hashed & read-only gaps recorded, never filled
02

Compute

Ten years of annual and forty quarters of standardised statements, then every metric: margins, DuPont, working-capital days, ROIC, FCF variants, accrual ratio. Forensics — Beneish M, Altman Z, Piotroski F, Sloan, Montier C. Credit, including Merton distance-to-default and a maturity ladder. Risk: beta raw and Blume, Jensen's alpha, Sharpe, Sortino, VaR and CVaR, drawdown and recovery, historical stress replays. Technicals and Fama–French regressions. Then the full valuation stack: driver-based DCF, reverse DCF, comps, Monte Carlo, earnings power, LBO ceiling, SOTP. Accounting identities are asserted — a balance sheet that does not balance raises rather than rounds.

every figure a pure function unit-tested against hand-checked values
03

Sixteen analysis phases

Business and moat, forensic accounting, management track record, product pipeline, industry structure, macro exposure, operations, governance, sentiment and positioning, technicals, legal and regulatory, valuation judgement, primary research, scenarios, and trade construction. Each receives the computed metrics as input and returns typed, validated output — the response contract has no field to put a free-floating number in, so the constraint is structural rather than an instruction the model is asked to follow.

04

Five-seat council

Five independent reviewers read the assembled analysis from different mandates and vote, and a chairman reconciles them. Disagreement is kept rather than averaged: the report shows the split, because four-of-five is a fact about a small panel and a percentage would launder it into something that sounds continuous. A seat that fails validation is retried with the error fed back, and if it still fails it is logged as a high-impact gap and shown — never silently dropped.

dispersion from the seats chairman verdict persisted
05

Red team

A dedicated adversarial pass whose only job is to attack the conclusion: find the strongest bear case, the load-bearing assumption, and the evidence that would falsify the thesis. It runs after the council so it has the actual argument to attack rather than a draft.

06

Bias checks

Structured checks for the failure modes this kind of pipeline actually has: anchoring on the current price, confirmation in the evidence selection, base-rate neglect in the scenarios, and false precision in the language. Each produces a finding attached to the section it affects.

07

Verifier

Every numeric claim in the draft is checked back against the computed figures, and every factual claim against its cited source. A claim that cannot be verified is removed; one that is unverifiable but load-bearing is kept and labelled as such. The verifier can only delete or flag — it can never add a number, so it cannot become a second author.

claims checked against computed values unverified claims removed
08

Report

Rendered with every figure carrying its provenance, every estimate carrying its range, and a manifest recording the model version, the snapshot hash, the git commit and the exact cost — so the same run can be rebuilt and audited later.

What this demo runs, and what it doesn't

Runs daily, free

Stages 1 and 2

The snapshot and the entire computation layer, for every covered ticker, rebuilt each weekday after the US close by a scheduled job. Free data sources only, so it costs nothing to run and can run unattended.

Runs on request, costs money

Stages 3 to 8

The AI phases, council, red team, bias checks and verifier are frontier-model calls measured in dollars per report, not cents. One full sample report is published here; running one per ticker per day is not something a class project can fund, which is why the free reports stop at stage 2 and say so.

The rules it will not break

1. The model never does arithmetic. Numbers come from Python or a cited source.

2. No fabricated data. A failed or missing source is recorded as a gap. Nothing is filled with a plausible value.

3. Point-in-time only. Every loader takes an as-of date and is tested for it.

4. One frozen snapshot per analysis. Hashed, read-only.

5. Everything typed and validated. No untyped dictionaries cross a module boundary.

6. Scraped text is untrusted. Document and web content is wrapped in delimited data blocks; instructions found inside it are never followed.

7. Reproducibility. Model version, seeds, snapshot hash and git commit in every run's manifest.

8. Cost control. Every model call passes one client that logs tokens and enforces per-call, per-run and per-session caps.
